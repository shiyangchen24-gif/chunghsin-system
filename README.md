# 忠欣蔬果三站整合（打勾單／異常表與交接表／報價單匯出）

三個網站共用新的 Supabase 專案 `aknxualjinfanuchtbwo`，採用清爽卡片式後台外觀（淺灰綠底、白色卡片、翠綠主色）、輸入暱稱即可使用（管理員用帳號登入）＋RLS，以及低流量即時同步。

> **狀態**：程式與 SQL 都已在**本機測試堆疊**（PostgreSQL 16 + 真的 PostgREST 12 + 模擬的 Auth／Realtime 閘道）通過完整測試。
> **還沒有**部署到你的 Supabase 專案，也還沒用真實資料跑過：這個雲端環境到目前為止仍連不到 `*.supabase.co`。

## 部署步驟

部署方式：整個資料夾放進同一個 GitHub repo（例如 `zhongxin`），開啟 GitHub Pages，就是一個完整網站：
`…github.io/zhongxin/` 是首頁，`/tick/`、`/report/`、`/quote/` 是三個獨立頁面。每一頁左側都有共用側邊欄可以切換，三頁共用同一次登入。

**側邊欄**：桌機固定在左側，可收合成只剩圖示（會記住設定）；手機與平板（寬度小於 900px）從左下角按鈕開啟抽屜，按 Esc 或點旁邊關閉。管理員登入後才會多出「裝置管理」與「資料搬移」項目。列印時側邊欄完全隱藏，不影響原本的列印與 Excel 格式。

1. **建立結構**：在新專案的 SQL Editor 依序執行 `02_core_shared` → `03_tick` → `04_report` → `05_quote` → `06_import_staging` → `12_dashboard`（儀表板彙總）→ `13_nickname_access`（暱稱使用＋裝置 IP）→ `14_analytics`（異常分析與經營月報）→ `15_api_grants`（**必跑**：明確授權網頁存取資料表）。
   Supabase 自 2026-05-30 起的新專案、2026-10-30 起所有專案，新資料表不再自動開放給網頁（Data API），沒跑 15 網頁會出現 `permission denied`（42501）。之後若新增資料表，也要再跑一次 15。新專案是空的，所以 `01_backup` 可以略過。
2. **Realtime 設定**：Dashboard → Realtime → Settings，關閉「Allow public access」，只讓登入成員收到私有頻道的推播。
   **開啟暱稱使用**：Authentication → Sign In / Providers → 開啟「Allow anonymous sign-ins」。沒開的話，輸入暱稱時會提示「暱稱登入尚未開啟」，只能用帳號登入。
3. **建立管理員帳號**：Authentication → Users → Add user，然後修改 `11_members_template.sql` 裡的 Email 與角色後執行。一般同仁不需要帳號，輸入暱稱即可使用。
4. **搬移資料**：用管理員帳號開啟 `tools/migrate.html` → 「檢查來源筆數」→「開始搬移」。工具只讀取舊專案，可以重複執行。
5. **轉換與核對**：執行 `07_backfill.sql` → `08_verify.sql`。每一列 `ok` 都要是 `true`；最後一段列出的同名客戶（例如同一個店名對到兩個代號）請到 `legacy_name_review.resolved_code` 指定後，再跑一次 07。
6. **收回匿名權限**：執行 `09_cutover.sql`（先把檔案開頭 `-- set zx.confirm = 'cutover';` 前面的 `-- ` 刪掉，這是防誤按的安全鎖）。新專案與舊專案是分開的，這一步**不會**影響舊網站，只是讓新專案的資料一律要登入才能存取；要回復可用 `99_rollback.sql`。
7. **停用舊系統**：新網站用順、資料確認無誤後，再停用三個舊 Supabase 專案與舊的 GitHub Pages。

## 使用方式：輸入暱稱即可，不需帳號

- 第一次開啟網站時輸入暱稱（最多 12 字）就能使用，同一個瀏覽器之後不用再輸入。暱稱會顯示在打勾單的「最後操作者」等紀錄上，右上角可「改暱稱」。
- 暱稱裝置的權限等同一般同仁（staff）：可讀寫，不能刪除。刪除、資料搬移、裝置管理仍只限管理員帳號。
- 背後是 Supabase 的匿名登入：每個瀏覽器拿到一組專屬的裝置代號，資料仍受 RLS 保護。清除瀏覽器資料或換瀏覽器，會被當成新裝置。
- **裝置管理**（`tools/devices.html`，只限管理員）：列出每台裝置的暱稱、目前 IP、第一次 IP、IP 歷程、最後上線、瀏覽器。可以改暱稱、停用（停用後立即無法讀寫），也可以關閉「允許新裝置以暱稱使用」，只讓已登記的裝置繼續使用。
- **IP 說明**：IP 從 Supabase 請求標頭取得（`cf-connecting-ip` → `x-forwarded-for` 第一段 → `x-real-ip`），是裝置對外的網路 IP，同一個公司 Wi-Fi 下的多台裝置會顯示相同 IP。部署後請在裝置管理頁確認 IP 有正確顯示；本機測試環境是用模擬的標頭驗證的。
- **風險提醒**：只要知道網址，任何人都能輸入暱稱進來讀寫資料。建議網址不要外流，並定期到裝置管理查看陌生裝置；人員穩定後可以關閉「允許新裝置以暱稱使用」。

## 儀表板（首頁）

登入後顯示今天的重點，資料來自單一唯讀 RPC `dashboard_summary`（一次約 3 KB，不下載明細）：

- **四張重點卡**：今日已叫貨（x / 總家數、完成率、前一營業日家數）、三天未叫、近 7 天異常（與前 7 天比較的增減）、報價可批次匯出（另列待上傳／待設定格式）。點卡片直接進該系統。
- **叫貨趨勢**：平滑曲線，已叫貨（綠色實線＋淡色面積）與未叫貨（磚紅虛線），可切換 30／14／7 天，滑過顯示當天數字，也可展開成資料表。今天尚未結束時以空心點表示。
- **今日叫貨進度**：完成率環形量表、已叫／不叫／未叫／三天未叫的家數，以及各系列的已叫貨進度條（規則與打勾單「系列統計」相同）。
- **異常狀態分析**：可切換 7／30／90 天。一句話摘要（筆數與前一期比較、最常見類別、主要處理方式、責任歸屬），以及「異常類別」「處理方式」「責任歸屬」的比例長條和異常最多的店家。資料來自 `report_analysis`。
- **最新異常紀錄**：最近 4 筆異常卡片。
- 任何一站有異動時，儀表板最快每 60 秒重抓一次彙總，避免打勾高峰時每勾一次就重抓。

## 各站變更重點

**共通**
- 登入後才看得到資料。角色分 admin／staff／viewer；所有刪除都只限 admin（只改 `private.can_delete()` 一行就能調整）。
- 同步方式：一次異動只推送一則不到 600 bytes 的小事件給其他裝置。Realtime 斷線時每 30 秒做一次輕量檢查（無變更時不到 100 bytes），重連或切回分頁時立即補同步。
- 防覆寫：每筆資料都有版本號，畫面過期時寫入會被拒絕並提示；斷線重送不會重複寫入。

**打勾單**
- 原本每勾一次就讀寫兩大份 JSON，現在一勾只寫一列。重置由伺服器決定營業日，兩台同時按只會有一台成功。
- 「三天未叫」改由伺服器自動計算（連續 3 個工作天未叫貨），手動標示仍保留。
- 系列統計改存資料庫，新增「⚙ 系列設定」可自行新增系列與店家。
- 歷史不再只保留 6 天。刪除客戶改為「從打勾單移除、保留歷史」。
- 「📅 更新日期」按鈕已移除：日期改由伺服器營業日管理，這個功能已無作用。
- 頁首原本的「打勾單／異常表交接表」切換標籤，改由共用側邊欄取代。
- 修正原版小 bug：卡片底部會出現「ed」字樣（`'ordered'.slice(5)`）。

**異常表與交接表**
- 改為依日期範圍顯示（今天／近 7 天／近 30 天／全部／自訂），每頁 50 筆，可「載入更多」。
- 「刪除全部」只刪目前篩選的範圍，而且只限 admin。
- 輸入店家時會帶入車號，並標示來源（客戶車輛設定或最近一筆紀錄）。
- 正在編輯的那一列若被別台改過，會保留草稿並提示「資料已在別處更新」。
- 列印預覽與 Excel 匯出的程式碼逐字沿用原版：A4 橫式、每頁 16 筆、交接表至少 18 筆、欄寬列高、字型字級都已核對。

**報價單**
- 大型 JSON 拆成獨立資料表，首頁只讀輕量清單，品項只在開詳情、上傳或匯出時才讀。
- 匯出期間若有人重新上傳，該客戶不會被誤標為已匯出。
- 品項主檔在瀏覽器快取，版本有變才重新下載。
- **修正原版 bug**：「自動排除 Excel 隱藏列」其實從未生效，因為原版沒有傳 SheetJS 的 `cellStyles: true`。

## Egress 試算（`docs/egress-estimate.md`）

單次大小已用本機實測校正：寫入回應 207 B、推播每台 391 B、心跳 89 B、打勾單首載每位客戶約 430 B。
試算結果（含儀表板 2 台、異常分析與月報）：8 台約 **1.03 GB／月**，10 台約 **1.16 GB／月**，內部預算是 3 GB。這是未壓縮的數字；真實 Supabase 有 gzip，實際應該更低，仍須以 Dashboard Usage 對帳。
對照：依原程式碼推算，舊版打勾單如果全表 300 KB，每月約 125 GB。
